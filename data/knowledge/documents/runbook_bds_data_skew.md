# BDS 计算任务长尾与数据倾斜处置手册

本手册适用于合成环境中 BDS 聚合任务整体进度长期停留在最后若干 task、单个 stage 耗时远超历史基线的场景。所有指标阈值均为演示用途。

## 适用症状

- BDS 任务某个 stage 的 99 分位 task 耗时是中位数的十倍以上。
- 绝大多数 task 已完成，剩余极少数 task 长时间处于 `running`。
- 任务未失败，但结束时间远超 SLA，导致下游 LTS 报表任务超时。

## 确认步骤

1. 读取该任务各 stage 的 task 耗时分布，定位长尾 stage。
2. 读取长尾 stage 的输入分片大小分布，确认是否存在单分片体积显著偏大。
3. 读取该 stage 的 shuffle 读写量，确认倾斜发生在读取端还是聚合端。
4. 读取参与聚合的 key 分布统计，确认是否存在单一 key 占比过高。

## 根因判定

- 聚合 key 分布倾斜：某个业务 key（例如默认值、空值占位或超大商户）占据了绝大部分记录，导致单个 reduce task 承担全部压力。
- 输入分片不均：上游产出的文件大小差异极大，读取阶段即已倾斜。
- 关联维表膨胀：join 一侧存在重复 key，导致中间结果规模远超预期。

## 处置步骤

1. 若为聚合 key 倾斜，与业务方确认该 key 是否为无效占位；确认后在聚合前过滤或对该 key 单独加盐拆分再合并。
2. 若为输入分片不均，请上游任务负责人调整产出文件的合并策略，使单文件规模落在合理区间。
3. 若为维表膨胀，先核对维表主键唯一性，再决定是修复维表还是在 join 前去重。
4. 任何调整都需要用一次完整跑批验证结果记录数与历史口径一致，倾斜缓解不能以口径变化为代价。

## 禁止操作

- 不允许仅通过提高并行度或扩容资源掩盖倾斜，单个热点 task 不会因为总资源变多而变快。
- 不允许直接跳过长尾 stage 或提前终止任务后把不完整结果当作产出。

## 升级条件

若 key 分布、分片大小与维表主键三项均正常，但长尾仍稳定复现，应升级至计算平台负责人排查执行计划或引擎版本变更。
