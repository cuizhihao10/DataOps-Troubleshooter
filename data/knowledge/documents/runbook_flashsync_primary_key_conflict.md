# FlashSync 同步任务主键冲突处置手册

本手册适用于合成环境中的 FlashSync 增量同步任务在写入目标表时报 `duplicate key value violates unique constraint` 的场景。全部命令与标识均为演示用途，不指向任何真实系统。

## 适用症状

- FlashSync 任务状态由 `running` 变为 `failed`，错误摘要包含 `duplicate key` 或 `unique constraint`。
- 同一批次重试仍然失败，失败位点始终落在同一批增量文件上。
- 下游 BDS 聚合任务因上游数据未就绪而排队等待，LTS 报表任务随之超时。

## 确认步骤

1. 读取 FlashSync 任务最近一次运行的错误摘要，确认冲突的目标表与唯一约束名称。
2. 读取该任务的同步位点与批次窗口，确认失败批次覆盖的时间范围。
3. 读取源端增量文件的主键分布统计，确认同一主键在单批次内是否出现多条记录。
4. 读取目标表最近一次全量或修复写入记录，确认是否存在与本批次重叠的历史写入。

## 根因判定

出现主键冲突通常只有两种成因，必须先区分再处置：

- 源端单批次内重复：上游变更日志在同一窗口内包含同一主键的多次变更，而同步任务按 append 语义写入。此时冲突来自源数据本身，重跑无效。
- 目标端历史残留：上一次失败任务已部分写入目标表但位点未推进，重跑时重复写入同一批记录。此时冲突来自位点与实际写入不一致。

## 处置步骤

1. 若判定为源端单批次内重复，请数据源负责人确认该主键的业务语义，并将同步任务的写入语义由 append 调整为按主键 upsert；调整需走变更评审。
2. 若判定为目标端历史残留，先由 DBA 核对目标表中该批次已写入的记录数，再决定是清理该批次已写入记录后重跑，还是直接推进位点跳过已写入部分。
3. 两种情况都需要在处置后重新校验目标表主键唯一性与记录总数，确认与源端批次统计一致。
4. 处置完成并确认同步恢复后，再手动触发下游 BDS 聚合任务，不要在 FlashSync 未恢复时提前触发。

## 禁止操作

- 不允许直接删除目标表或以 `TRUNCATE` 方式清空后重灌全量数据。
- 不允许绕过唯一约束（例如临时删除约束再写入）以让任务"跑过去"。
- 不允许在未确认根因的情况下反复重试同一批次，重试只会重复产生同类错误并拉长恢复时间。

## 升级条件

若确认步骤无法区分上述两种成因，或目标表记录数与源端统计差异超过单批次规模，应升级至数据平台值班同学共同排查，不要自行推进位点。
