# LTS 调度参数校验失败标准处置流程

本流程适用于合成环境中 LTS 调度任务在提交阶段即被拒绝、错误信息指向运行参数校验的场景。所有参数名与取值均为演示用途。

## 适用症状

- LTS 任务在 `submitting` 阶段直接进入 `failed`，未产生任何计算资源占用。
- 错误摘要包含 `invalid partition parameter`、`parameter validation failed` 或类似措辞。
- 同一任务的历史成功运行使用了不同的分区参数取值。

## 确认步骤

1. 读取 LTS 任务本次运行的完整参数列表，重点确认分区字段名、分区取值与时间格式。
2. 读取该任务最近一次成功运行的参数列表，与本次逐项比对，定位发生变化的参数。
3. 读取任务定义的最近变更记录，确认参数变化是人工调整还是模板变量替换失败导致。
4. 读取上游依赖任务的产出分区，确认所需分区是否真实存在。

## 根因判定

参数校验失败几乎不会是调度器自身故障，常见成因按出现频率排序：

- 时间模板变量未正确替换，导致分区取值仍是字面量占位符。
- 分区取值指向一个上游尚未产出的分区，校验阶段即被拒绝。
- 任务定义变更引入了目标表并不存在的分区字段名。

## 处置步骤

1. 若为模板变量未替换，修正任务定义中的变量写法并在提交前用调度器的参数预览功能确认渲染结果。
2. 若为上游分区缺失，先确认上游任务状态；上游未完成时应等待或修正依赖配置，不要通过改写分区取值绕过。
3. 若为字段名错误，与表结构负责人确认目标表当前分区字段，再更新任务定义。
4. 修正后先做一次单分区试跑，确认校验通过并产出预期记录数，再恢复常规调度。

## 禁止操作

- 不允许为了让任务提交成功而关闭参数校验或降低校验级别。
- 不允许把分区取值改成一个"肯定存在"的历史分区来让任务跑通，这会产出错误口径的数据。

## 升级条件

若参数预览渲染结果正确、上游分区确实存在、字段名也与表结构一致，但校验仍然失败，则应升级至调度平台负责人排查校验规则本身的变更。
